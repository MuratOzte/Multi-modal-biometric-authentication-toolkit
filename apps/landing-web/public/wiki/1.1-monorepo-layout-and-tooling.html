Purpose and Scope

This page details the structural layout, workspace organization, and script tooling of the SecureKit multi-modal biometric authentication toolkit monorepo. It covers pnpm workspace definitions, root package.json task orchestration, build/typecheck/test pipelines, and the physical directory layout (apps/, packages/, python/, and scripts/).

Root Tooling and package.json Configuration

The root package.json specifies strict engine requirements and package manager versions, enforcing Node >=22.12.0 and pnpm@9.15.9 package.json 32-35 Workspace globs cover all subdirectories under packages/* and apps/* package.json 4-7

Root Script Definitions

Root scripts drive the primary development, building, and validation lifecycles:

  • Build: "pnpm -r build" recursively builds all packages package.json 9
  • Development: "node scripts/dev.mjs" and "node scripts/dev.mjs node" manage local orchestrations package.json 10-11
  • Typechecking: "pnpm -r --if-present typecheck" evaluates TypeScript types across workspaces package.json 13
  • Testing: Scoped workspace test filters target specific verification modules, such as @securekit/node-auth and @securekit/web-sdk package.json 14
  • Parity & Acceptance: Integration tests build the .NET solution (SecureKit.slnx) and execute Node-based runners like scripts/aspnet-parity.mjs package.json 19-21

Build, Parity, and Test Pipelines

The test and parity tooling bridges Node.js orchestration scripts with .NET and Python executables. For instance, scripts/aspnet-parity.mjs systematically executes stage-by-stage parity verification between the legacy Node/Express API and the modern ASP.NET Core backend.

The parity script spawns each stage script (from stage one to seven) using tsx scripts/aspnet-parity.mjs 11-14 captures output logs scripts/aspnet-parity.mjs 17-22 extracts comparison summaries scripts/aspnet-parity.mjs 24 and persists structured JSON reports into .run-logs/aspnet-parity.json scripts/aspnet-parity.mjs 7
