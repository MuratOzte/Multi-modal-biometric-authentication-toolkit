Python Process Bridge

The Python Process Bridge is the subsystem responsible for managing the lifecycle, input/output streaming, and error handling of external Python biometric verification workers (CardPython, FacePython, VoicePython, KeystrokePython) from the ASP.NET Core backend. It handles process discovery across virtual environments, establishes JSON-lines-based communication over standard input/output, enforces strict execution timeouts, and guarantees process-tree termination to prevent zombie worker processes.

1. Worker Discovery and Environment Resolution

The C# orchestration layer discovers and launches Python runtimes dynamically based on configuration parameters and local workspace conventions. The CardOptions class resolves paths for the script, temporary directories, and fallback search paths [apps/securekit-api/Services/CardOptions.cs:12-25].

The CardPython implementation iterates through a prioritized list of runtime candidate locations (Candidates()), evaluating virtual environments (.venv-card, .venv) before falling back to system-level interpreters (py -3, python3, python) [apps/securekit-api/Services/CardPython.cs:22-43]. If a dependency failure occurs (such as a missing Python package), the process bridge captures standard error output and translates the exception into a structured HTTP-mapped failure response [apps/securekit-api/Services/CardPython.cs:27-31, 80-87].

2. CLI Contracts and Stdin/Stdout JSON-Lines Protocol


Once a worker process is spawned, communication is established via a synchronous, line-oriented JSON protocol over standard input and standard output streams.

3. Timeouts, Error Handling, and Process-Tree Termination


To prevent hanging worker threads or leaked OS resources during intensive computer vision tasks, CardPython wraps execution in linked cancellation tokens and process job containers.


    

  • Timeouts: A CancellationTokenSource is bound to options.TimeoutMs (defaulting to 300,000ms / 5 minutes) [apps/securekit-api/Services/CardPython.cs:60-61]. If execution exceeds this window, an OperationCanceledException is intercepted and converted into a PYTHON_TIMEOUT failure code (504 Gateway Timeout) [apps/securekit-api/Services/CardPython.cs:77-78].
    • 

  • Process-Tree Kill: ProcessJob.Attach(process) registers the child process within a job object [apps/securekit-api/Services/CardPython.cs:68]. In the finally cleanup block, if the process has not exited, process.Kill(true) is invoked recursively to terminate the entire process tree, preventing orphaned Python sub-processes [apps/securekit-api/Services/CardPython.cs:88-96].
    • 

  • Stderr Drainage: Standard error is drained asynchronously via DrainError to prevent pipe deadlocks when stderr buffers fill up during exceptions or warnings [apps/securekit-api/Services/CardPython.cs:69].

4. Temporary Files and Data Flow


Biometric verification pipelines often ingest high-resolution image or audio payloads. The process bridge coordinates data handoff by streaming inputs directly or referencing managed paths validated by CardOptions.Allowed [apps/securekit-api/Services/CardOptions.cs:28-41].


Path security constraints ensure that referenced reference images and temporary upload paths reside strictly within permitted roots (ReferenceDirectory, UserReferenceDirectory), preventing directory traversal vulnerabilities prior to spawning worker CLI arguments [apps/securekit-api/Services/CardOptions.cs:15-16, 24-41].
