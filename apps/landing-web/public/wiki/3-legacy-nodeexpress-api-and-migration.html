node-auth Routes and Services

The legacy backend is built around an Express application initialized in packages/node-auth/src/server.ts. It mounts modular routers under distinct prefixes to manage multi-modal verification workflows. These include authentication (auth.ts), dynamic/static text challenges (challenge.ts), user consent (consent.ts), biometric profile metadata (profiles.ts), and modal verification endpoints (face, voice, keystroke, card, and network/session evaluation).

For details, see node-auth Routes and Services.

Migration Plan to ASP.NET Core 10

Migrating away from the Node/Express implementation involves an endpoint-by-endpoint porting effort into apps/securekit-api. The migration strategy preserves strict response schema contracts, error envelope formatting (VALIDATION_ERROR, UNAUTHORIZED, INTERNAL_ERROR), and ID normalization rules (trimming and lowercasing user identifiers where applicable) to guarantee seamless interoperability with @securekit/web-sdk and the React demo application.

For details, see Migration Plan to ASP.NET Core 10.

Sources: docs/NODE_API_CONTRACT_INVENTORY.md:1-29

Cutover and Parity Testing

To ensure zero regression during the cutover phase, a comprehensive parity testing harness runs automated differential checks between the legacy Node implementation and the ASP.NET Core backend. The testing framework relies on incremental stage scripts (test:aspnet-stage1 through test:aspnet-stage7) defined in package configurations, executing end-to-end payload comparisons against shared test fixtures.
