The packages/node-auth package provides the legacy Node.js and Express-based API backend for the SecureKit toolkit packages/node-auth/package.json 1-37 It exposes multi-modal biometric authentication routes, challenge generation, session lifecycle management, and profile storage prior to full migration to ASP.NET Core docs/NODE_API_CONTRACT_INVENTORY.md 1-6 This page details the server bootstrap, Express routers, storage modules, and request/response contracts implemented in this package.

Server Bootstrap and Middleware Setup (server.ts)

The Express application is bootstrapped in packages/node-auth/src/server.ts (referenced via docs/NODE_API_CONTRACT_INVENTORY.md). It configures global middleware, global error handling, body parsing limits, and mounts all feature routers under standard base paths.

Key Configuration Parameters

  • Base URL / Port: Typically hosted on http://localhost:3001 docs/NODE_API_CONTRACT_INVENTORY.md 10
  • CORS: Enabled globally via cors() permitting all origins without credential exposure docs/NODE_API_CONTRACT_INVENTORY.md 13
  • Payload Limits: JSON body parser size is capped at 2mb docs/NODE_API_CONTRACT_INVENTORY.md 13-14
  • Error Envelope: Non-parser route failures return structured JSON matching {"error":{"code":"...","message":"...","details":{}}} docs/NODE_API_CONTRACT_INVENTORY.md 14-16

Express Routers and Endpoint Contracts

The API surface is partitioned into specialized Express routers located under packages/node-auth/src/routes/ docs/NODE_API_CONTRACT_INVENTORY.md 31-33

1. Health and Authentication (auth.ts, legacyVerification.ts)

  • GET /health: Returns application health status 200 {"ok":true} docs/NODE_API_CONTRACT_INVENTORY.md 37
  • GET /auth/users: Lists registered user records with creation and update timestamps docs/NODE_API_CONTRACT_INVENTORY.md 38
  • POST /auth/register: Registers a new user with userId and password. Returns 201 on creation or 200 if identical parameters exist docs/NODE_API_CONTRACT_INVENTORY.md 39
  • POST /auth/login: Authenticates credentials, returning 200 on success or 401 INVALID_CREDENTIALS on mismatch docs/NODE_API_CONTRACT_INVENTORY.md 40

2. Challenges (challenge.ts)

  • POST /challenge/text: Generates text verification challenges with configurable language (lang), length (length), and wordCount (defaulting to Turkish, short length, 120-second TTL) docs/NODE_API_CONTRACT_INVENTORY.md 41-48
  • POST /challenge/text/consume: Consumes a challenge ID single-use token, returning errors (404, 410, 409) if invalid, expired, or already used docs/NODE_API_CONTRACT_INVENTORY.md 42-48

3. Consent and Profiles (consent.ts, profiles.ts)

  • POST /consent: Records user consent versions and timestamps docs/NODE_API_CONTRACT_INVENTORY.md 43
  • GET /user/:userId/profiles: Retrieves stored biometric profile references (keystroke, face, card, voice) for a given user docs/NODE_API_CONTRACT_INVENTORY.md 44
  • DELETE /user/biometrics: Clears stored biometric profiles and optionally consent records when ?deleteConsent=true is provided docs/NODE_API_CONTRACT_INVENTORY.md 45-50

4. Sessions and Risk Evaluation (session.ts, session/inMemoryStore.ts)

  • POST /session/start: Initializes a session with a default 900-second TTL docs/NODE_API_CONTRACT_INVENTORY.md 66-69
  • POST /verify/session: Evaluates risk scores, policy compliance, and signal aggregations (location, network, voice, keystroke), yielding decisions of allow, step-up, or deny along with requiredSteps docs/NODE_API_CONTRACT_INVENTORY.md 67-75

Storage Modules and Data Layer

The node-auth package relies on lightweight in-memory and file-backed storage utilities to manage user registries, active challenges, and verification sessions.

  • Normalization Rules: User IDs are processed with .trim().toLowerCase() in authentication and card routers, and regular .trim() in secondary routers docs/NODE_API_CONTRACT_INVENTORY.md 25-26
  • State Stores: Transient states such as session timeouts and challenge consumption flags are maintained via inMemoryStore.ts modules to support fast validation cycles during testing and development docs/NODE_API_CONTRACT_INVENTORY.md 61-62
