Purpose and Scope

This section covers the storage mechanisms and configuration infrastructure of the SecureKit ASP.NET Core API (apps/securekit-api). SecureKit utilizes lightweight file-based JSON stores (FileUserStore, ProfileStorage, and FixedKeystrokeStore) to manage user records, biometric profiles, and keystroke templates without requiring an external database. Configuration is managed via appsettings.json and extended through hierarchical environment variable overrides, enforcing security boundaries via strict reference root validation and atomic write guarantees.

Sources: docs/ASPNET_CUTOVER.md:34-37, apps/securekit-api/appsettings.json:1-35

File-Based JSON Stores and Concurrency

The storage subsystem relies on local file persistence to store state across restarts. By default, stores are initialized under the apps/securekit-api/.securekit directory or overridden via specific environment variables docs/ASPNET_CUTOVER.md 34

Key components of the storage layer include:

  • FileUserStore: Manages user credentials, salts, and identity hashes. The file path is configurable via SECUREKIT_USERS_FILE docs/ASPNET_CUTOVER.md 43
  • ProfileStorage: Stores multi-modal biometric profile mappings, tracked via SECUREKIT_PROFILE_STORE docs/ASPNET_CUTOVER.md 44
  • FixedKeystrokeStore: Manages fixed keystroke templates and reference inputs, tracked via SECUREKIT_KEYSTROKE_STORE docs/ASPNET_CUTOVER.md 45

To prevent race conditions and partial writes during concurrent requests, the storage layer employs atomic write patterns and process-level file locking.

Configuration Architecture (appsettings.json)

The API behavior is driven by structured configuration sections defined in apps/securekit-api/appsettings.json. The configuration schema maps directly to strongly-typed options classes used throughout the service layer.

The configuration layout contains the following primary blocks:

  • Logging: Defines Microsoft ASP.NET and default log levels apps/securekit-api/appsettings.json 2-7
  • Face: Controls face verification constraints, upload limits, timeout thresholds, device selection (auto), and GPU enforcement apps/securekit-api/appsettings.json 9-15
  • Voice: Configures speaker verification parameters, minimum enrollment samples, Whisper model tiers, and ECAPA-VoxCeleb embeddings apps/securekit-api/appsettings.json 16-26
  • Card: Defines OCR timeouts, upload limits, and default matching thresholds apps/securekit-api/appsettings.json 27-31
  • Cors: Manages allowed cross-origin resource sharing policies apps/securekit-api/appsettings.json 32-34

Environment Variable Overrides and Reference Roots

ASP.NET Core allows overriding any hierarchical configuration key using double-underscore (__) syntax in environment variables. This mechanism is heavily used for deployment customization, file path redirection, and strict boundary enforcement for biometric references.

Important environment variables and path mappings include:

  • SECUREKIT_USERS_FILE: Absolute path override for the user store docs/ASPNET_CUTOVER.md 43
  • SECUREKIT_PROFILE_STORE: Absolute path override for user profiles docs/ASPNET_CUTOVER.md 44
  • SECUREKIT_KEYSTROKE_STORE: Directory path for fixed keystroke models docs/ASPNET_CUTOVER.md 45
  • Face__ReferenceDirectory / FACE_SLIDING_REFERENCES_ROOT: Storage roots for face embedding references docs/ASPNET_CUTOVER.md 46-47
  • Card__UserReferenceDirectory: Storage root for verified ID card templates docs/ASPNET_CUTOVER.md 48
  • Face__AllowedReferenceRoots__0 / Card__AllowedReferenceRoots__0: Explicit security constraints restricting file access to authorized reference directories docs/ASPNET_CUTOVER.md 58-59
  • MOCK_IP_CHECK: Flag to bypass live IP/VPN geolocation checks during development docs/ASPNET_CUTOVER.md 49
