Local Development Orchestration (scripts/dev.mjs)

The local development workflow is managed by the orchestration script scripts/dev.mjs. This script inspects runtime arguments or environment variables to determine whether to launch the modern ASP.NET Core 10 backend (apps/securekit-api) or the legacy Node/Express API (packages/node-auth), alongside the React demo application (apps/demo-web) scripts/dev.mjs 1-40

Process Lifecycle and Signal Handling

When executing pnpm dev or pnpm dev:node, scripts/dev.mjs performs the following steps:

  1. Resolves the repository root and the target backend (aspnet or node), defaulting to aspnet if unspecified scripts/dev.mjs 5-7
  2. If aspnet is selected, it asynchronously runs dotnet build apps/securekit-api to compile the C# solution scripts/dev.mjs 25-29
  3. Spawns the compiled API executable (SecureKit.Api.dll) or the Node server (src/server.ts via tsx), attaching stdin/stdout/stderr via stdio: "inherit" scripts/dev.mjs 16-34
  4. Spawns the Vite development server for apps/demo-web, injecting proxy environment variables that point to the active backend scripts/dev.mjs 35-38
  5. Listens for termination signals (SIGINT, SIGTERM) to cleanly terminate all spawned child processes via process-tree traversal scripts/dev.mjs 10-40

Port Allocations and Vite Proxy Resolution


SecureKit utilizes a strict port layout for local integration testing and browser access:


    

  • 3002: ASP.NET Core 10 API (apps/securekit-api) default port docs/ASPNET_CUTOVER.md 8
    • 

  • 3001: Legacy Node/Express API (packages/node-auth) default port docs/ASPNET_CUTOVER.md 10
    • 

  • 5173: Vite development server for apps/demo-web docs/ASPNET_CUTOVER.md 8
    • 



Proxy Target Resolution Hierarchy


The Vite development server uses a proxy layer to route API calls from /api/securekit to the chosen backend docs/ASPNET_CUTOVER.md 28-30 The proxy target is resolved using a fallback hierarchy evaluated by scripts/dev.mjs and Vite configuration:


    

  1. VITE_SECUREKIT_DEV_PROXY_TARGET: If an explicit non-empty URL is provided in the environment, it takes absolute precedence docs/ASPNET_CUTOVER.md 21
    2. 

  2. VITE_SECUREKIT_API_BACKEND: If set to aspnet, it targets http://localhost:3002; if set to node, it targets http://localhost:3001 docs/ASPNET_CUTOVER.md 22
    3. 

  3. Default Fallback: If neither is defined, it defaults to the ASP.NET Core API at http://localhost:3002 docs/ASPNET_CUTOVER.md 23
    4.

Backend Switching and Backward Compatibility


Developers can switch between backends dynamically depending on testing requirements.


Switching to ASP.NET Core (Default)


    

  1. Stop any running processes with Ctrl+C docs/ASPNET_CUTOVER.md 64
    2. 

  2. Ensure VITE_SECUREKIT_DEV_PROXY_TARGET is unset or points to http://localhost:3002 docs/ASPNET_CUTOVER.md 66
    3. 

  3. Run pnpm dev docs/ASPNET_CUTOVER.md 8
    4. 



Switching to Node/Express


    

  1. Stop running processes with Ctrl+C docs/ASPNET_CUTOVER.md 64
    2. 

  2. Run pnpm dev:node to launch the Express server on port 3001 and bind the Vite proxy accordingly docs/ASPNET_CUTOVER.md 10
    3. 





[!WARNING]
Both backends should never write to the same JSON state files simultaneously. Always shut down one backend instance before starting the other if sharing persistent store directories docs/ASPNET_CUTOVER.md 36-37
