This page details the HTTP endpoints, controller classes, routing behaviors, and request/response contracts implemented in the ASP.NET Core API (apps/securekit-api). The controllers act as the primary boundary layer, receiving incoming HTTP traffic (JSON payloads and multipart form uploads), validating inputs, interfacing with verification and storage services, and serializing responses into standardized JSON envelopes or error payloads.

1. Controller Architecture and Routing Overview

The API is built on ASP.NET Core 10 using attribute-routed controllers marked with the [ApiController] annotation apps/securekit-api/Controllers/CardController.cs 11-13

Endpoints maintain strict parity with the legacy Node/Express routes to ensure seamless compatibility with the @securekit/web-sdk and apps/demo-web MIGRATION_TO_ASPNET10_PLAN.md 5-14

The controller suite covers the following functional domains:

  • Health: System status probes (/health) apps/securekit-api.tests/HealthTests.cs 9-15
  • Auth: User registration, login, and enumeration (/auth/register, /auth/login, /auth/users) MIGRATION_TO_ASPNET10_PLAN.md 150-152
  • Challenge: Biometric and text challenge generation and single-use consumption (/challenge/text, /challenge/text/consume) MIGRATION_TO_ASPNET10_PLAN.md 99-100
  • Session & Profiles: Session initialization, sliding-window risk evaluation, profile querying, and user biometric wiping (/session/start, /verify/session, /user/{userId}/profiles, /user/biometrics) MIGRATION_TO_ASPNET10_PLAN.md 101-154
  • Biometric Verification (Card, Face, Voice, Keystroke, FixedKeystroke): Enrollment and verification endpoints handling multipart image/audio uploads and biometric telemetry.
  • Network: IP and VPN verification checks (/verify/network).

2. Request/Response Contracts and Error Envelopes

Endpoints communicate via JSON (application/json) or multipart form data (multipart/form-data) for file uploads (such as ID cards, face images, or voice samples).

Standard errors are wrapped in a consistent JSON envelope containing an error code, message, and optional details:

{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "referenceImage is required.",
    "details": null
  }
}

If an upload payload exceeds the configured maximum body size (CardOptions.MaxUploadBytes), the controllers catch BadHttpRequestException or InvalidDataException and return a 413 Payload Too Large status with an IMAGE_TOO_LARGE code apps/securekit-api/Controllers/CardController.cs 36-88

Sources: [apps/securekit-api/Controllers/CardController.cs:25-89], [apps/securekit-api.tests/HealthTests.cs:18-24]
