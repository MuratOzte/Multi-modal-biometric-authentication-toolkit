Bu sayfa, SecureKit çok modlu biyometrik kimlik doğrulama monoreposunun yerel geliştirme ortamını açıklar. Kök geliştirme betikleri, scripts/dev.mjs üzerinden süreç yönetimi, port dağılımı (ASP.NET Core için 3002, Node/Express için 3001, Vite demo-web arayüzü için 5173), ortam değişkenleri ve sunucu değiştirme adımları ele alınır.

Kaynaklar: docs/ASPNET_CUTOVER.md 1-110 scripts/dev.mjs 1-40 apps/demo-web/.env.example 1-4

Yerel geliştirme süreçlerinin yönetimi (scripts/dev.mjs)

Yerel geliştirme akışı scripts/dev.mjs betiğiyle yönetilir. Betik, React demo uygulamasıyla (apps/demo-web) birlikte yeni ASP.NET Core 10 sunucusunu (apps/securekit-api) veya eski Node/Express API’sini (packages/node-auth) başlatmak için komut argümanlarını veya ortam değişkenlerini inceler. scripts/dev.mjs 1-40

Süreç yaşam döngüsü ve sinyal yönetimi

pnpm dev veya pnpm dev:node çalıştırıldığında scripts/dev.mjs şu adımları uygular:

  1. Depo kökünü ve hedef sunucuyu (aspnet veya node) belirler; seçim belirtilmemişse aspnet kullanır. scripts/dev.mjs 5-7
  2. aspnet seçilmişse C# çözümünü derlemek için dotnet build apps/securekit-api komutunu asenkron çalıştırır. scripts/dev.mjs 25-29
  3. Derlenmiş API dosyasını (SecureKit.Api.dll) veya Node sunucusunu (tsx üzerinden src/server.ts) başlatır; stdin/stdout/stderr akışlarını stdio: "inherit" ile bağlar. scripts/dev.mjs 16-34
  4. apps/demo-web için Vite geliştirme sunucusunu başlatır ve etkin sunucuyu gösteren proxy ortam değişkenlerini aktarır. scripts/dev.mjs 35-38
  5. Sonlandırma sinyallerini (SIGINT, SIGTERM) dinler ve süreç ağacını dolaşarak tüm alt süreçleri düzgünce kapatır. scripts/dev.mjs 10-40

Kaynaklar: scripts/dev.mjs 1-40

Port dağılımı ve Vite proxy hedefi

SecureKit, yerel entegrasyon testleri ve tarayıcı erişimi için sabit bir port düzeni kullanır:

  • 3002: ASP.NET Core 10 API (apps/securekit-api) varsayılan portu. docs/ASPNET_CUTOVER.md 8
  • 3001: Eski Node/Express API (packages/node-auth) varsayılan portu. docs/ASPNET_CUTOVER.md 10
  • 5173: apps/demo-web için Vite geliştirme sunucusu. docs/ASPNET_CUTOVER.md 8

Proxy hedefinin öncelik sırası

Vite geliştirme sunucusu, API çağrılarını /api/securekit üzerinden seçilen sunucuya ileten bir proxy katmanı kullanır. docs/ASPNET_CUTOVER.md 28-30 Hedef, scripts/dev.mjs ve Vite yapılandırması tarafından şu öncelik sırasıyla belirlenir:

  1. VITE_SECUREKIT_DEV_PROXY_TARGET: Ortamda açıkça belirtilmiş, boş olmayan bir URL varsa en yüksek önceliğe sahiptir. docs/ASPNET_CUTOVER.md 21
  2. VITE_SECUREKIT_API_BACKEND: aspnet değeri http://localhost:3002 adresini; node değeri http://localhost:3001 adresini hedefler. docs/ASPNET_CUTOVER.md 22
  3. Varsayılan hedef: İkisi de tanımlı değilse http://localhost:3002 adresindeki ASP.NET Core API kullanılır. docs/ASPNET_CUTOVER.md 23

Ortam değişkenleri ve yapılandırma

Yerel geliştirme yapılandırması, belirli paketlerdeki .env dosyalarıyla (örneğin apps/demo-web/.env.example) veya çalıştırıcıya terminalden aktarılan ortam değişkenleriyle yönetilebilir. docs/ASPNET_CUTOVER.md 25-27 apps/demo-web/.env.example 1-4

Örnek ortam yapılandırması (apps/demo-web/.env.example)

VITE_SECUREKIT_BASE_URL=/api/securekit
VITE_SECUREKIT_API_BACKEND=aspnet
# Optional explicit target (takes precedence over API_BACKEND):
# VITE_SECUREKIT_DEV_PROXY_TARGET=http://localhost:3002

Sunucu değiştirme ve geriye dönük uyumluluk

Geliştiriciler test gereksinimlerine göre sunucular arasında geçiş yapabilir.

ASP.NET Core’a geçiş (varsayılan)

  1. Çalışan süreçleri Ctrl+C ile durdurun. docs/ASPNET_CUTOVER.md 64
  2. VITE_SECUREKIT_DEV_PROXY_TARGET tanımlı olmasın veya http://localhost:3002 adresini göstersin. docs/ASPNET_CUTOVER.md 66
  3. pnpm dev komutunu çalıştırın. docs/ASPNET_CUTOVER.md 8

Node/Express’e geçiş

  1. Çalışan süreçleri Ctrl+C ile durdurun. docs/ASPNET_CUTOVER.md 64
  2. Express sunucusunu 3001 portunda başlatmak ve Vite proxy’sini buna bağlamak için pnpm dev:node komutunu çalıştırın. docs/ASPNET_CUTOVER.md 10

[!UYARI] Her iki sunucu aynı JSON durum dosyalarına eşzamanlı yazmamalıdır. Kalıcı depolama dizinleri paylaşılıyorsa diğer sunucuyu başlatmadan önce çalışan sunucuyu mutlaka kapatın. docs/ASPNET_CUTOVER.md 36-37
