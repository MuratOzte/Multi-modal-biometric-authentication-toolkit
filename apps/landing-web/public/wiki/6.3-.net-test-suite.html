The .NET Test Suite (apps/securekit-api.tests) is the integration and unit testing framework for the SecureKit ASP.NET Core API (apps/securekit-api). It validates controller endpoints, service layers, biometric Python process bridges, error translation contracts, and health monitors against expected behaviors and legacy Node.js API parity.

Test Architecture and Support Infrastructure

The test suite relies heavily on Microsoft.AspNetCore.Mvc.Testing to spin up in-memory instances of the API using WebApplicationFactory<TEntryPoint>. Custom test fixtures and helpers like ContractAssert validate JSON response shapes, HTTP status codes, and error structures.

For stage-specific tests, such as card verification integration (StageSevenTests), tests instantiate specialized web application factories that isolate file system operations, mock Python script execution paths, and override configuration keys (such as SECUREKIT_PROFILE_STORE, Card:ReferenceDirectory, and Card:ScriptPath).

Stage Seven and Card Verification Tests

StageSevenTests provides comprehensive coverage for card enrollment, reference listing, threshold validation, and Python worker bridge error mappings. The test factory sets up temporary storage roots and maps stub Python scripts (card-stage7.py) to simulate various success and failure conditions.

Key test behaviors implemented in StageSevenTests:

  • Reference Listing & Humanization: Ensures only valid image formats are listed and labels are properly formatted [apps/securekit-api.tests/StageSevenTests.cs:58-65].
  • Protocol & Decision Flow: Tests verification matches, best-match decisions, and automatic temporary file cleanup [apps/securekit-api.tests/StageSevenTests.cs:66-74].
  • Enrollment Normalization: Tests user ID sanitization, reference file replacement, and stored reference usage [apps/securekit-api.tests/StageSevenTests.cs:75-85].
  • Worker Error Mapping: Translates invalid outputs, schema failures, timeouts, and process errors into standard HTTP status codes (502, 504, 404) and error codes (PYTHON_OUTPUT_INVALID, PYTHON_TIMEOUT, REFERENCE_NOT_FOUND) [apps/securekit-api.tests/StageSevenTests.cs:86-100].
  • Input Validation: Rejects out-of-range thresholds (NaN, Infinity, -1, 2) and malformed file uploads [apps/securekit-api.tests/StageSevenTests.cs:101-112].

Health and Basic Contract Tests

HealthTests verifies basic service availability, contract parity with the legacy Node API, and boundary protections such as verifying that internal test endpoints remain hidden in production environments.

The test class injects ApiFactory to test:

  • Health Endpoint Contract: Validates that GET /health returns an HTTP 200 OK with the exact body {"ok":true} matching legacy contract expectations [apps/securekit-api.tests/HealthTests.cs:8-15].
  • Route Validation: Ensures required multipart fields like referenceImage correctly trigger a 400 Bad Request with structured error details when missing [apps/securekit-api.tests/HealthTests.cs:17-24].
  • Security Isolation: Confirms that internal infrastructure probe routes like /__test/throw are not exposed and correctly return 404 Not Found [apps/securekit-api.tests/HealthTests.cs:27-32].
