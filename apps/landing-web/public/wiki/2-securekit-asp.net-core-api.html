2.1 HTTP Endpoints and Controllers

The API exposes a comprehensive set of controller classes corresponding to the functional capabilities of the authentication workflow: user lifecycle management, challenge issuance, consent tracking, session evaluation, and multi-modal biometric verification (face, voice, ID card, dynamic and fixed keystrokes, network/IP checks, and health monitoring).

For detailed information on route definitions, input validation rules, and JSON request/response contracts, see HTTP Endpoints and Controllers.

2.2 Verification Services

The service layer encapsulates core security logic, multi-modal signal scoring, and Python worker execution bridges. Services such as FaceVerification, VoiceVerification, CardVerification, and SessionKeystrokeVerifier process raw inputs and interact with external Python scripts through stdin/stdout subprocess wrappers (FacePython, VoicePython, CardPython, KeystrokePython).

For a detailed breakdown of service implementations, risk calculation policies, and Python process inter-op, see Verification Services. For low-level details on subprocess execution, see Python Process Bridge, and for scoring algorithms, see Keystroke, Session and Risk Services.

2.3 Storage and Configuration

SecureKit uses file-based JSON storage adapters (FileUserStore, FileProfileStorage, FixedKeystrokeStore) alongside in-memory stores (SessionStore, ChallengeStore) to manage user credentials, biometric profiles, active tokens, and single-use challenges. State mutations are protected by atomic file write patterns and thread synchronization primitives to prevent corruption under concurrent requests.

For details on schema layouts, atomic locking strategies, and environment variable overrides, see Storage and Configuration.
