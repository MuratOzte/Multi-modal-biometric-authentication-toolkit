The @securekit/web-sdk package (packages/web-sdk) serves as the primary browser-side client library for SecureKit. It provides modular utilities for capturing biometric keystroke dynamics, collecting contextual browser and location signals, communicating with the SecureKit API transport layer, and maintaining backward compatibility through legacy client surfaces.

Client Initialization and Core Architecture (client.ts)

The core entry point of @securekit/web-sdk is responsible for initializing the authentication client, managing configuration options (such as API base URLs, timeouts, and headers), and orchestrating the registration of biometric collectors. The client instance acts as a facade that aggregates transport mechanisms, keystroke monitoring bindings, and environmental signal collectors.

Transport Layer and Adapters

The transport layer handles HTTP communication between the browser SDK and the backend API (apps/securekit-api or legacy packages/node-auth). It abstracts request serialization, authentication headers, error handling, and endpoint resolution based on environment variables like VITE_SECUREKIT_BASE_URL and VITE_SECUREKIT_API_BACKEND.

Keystroke Collectors

The keystroke collector captures real-time user typing rhythm by listening to keydown and keyup DOM events on designated input fields or forms. It records hold times (dwell time) and flight times (latency between consecutive keystrokes) to construct biometric profiles.

  • Dwell Time: Duration between keydown and corresponding keyup events for a single key.
  • Flight Time: Duration between keyup of a preceding key and keydown of the succeeding key.
  • Dynamic/Fixed Scoring: Prepares raw event streams to be validated against both free-text dynamic typing models and fixed-text biometric templates.

Location and Context Signals

To support risk evaluation and device fingerprinting, the web SDK includes location and environment collectors. These modules gather contextual signals such as timezone offset, screen resolution, browser language, and optional geolocation coordinates (subject to user permission prompts), which are bundled into authentication challenge payloads.

Sources: README.md 13-14

Legacy Client Surface

To maintain compatibility with older applications or during migration phases between legacy Express endpoints (packages/node-auth) and ASP.NET Core controllers (apps/securekit-api), the SDK provides a legacy client surface. This adapter layer exposes backwards-compatible method signatures that map legacy request payloads to the updated API contracts without requiring client code rewrites.
