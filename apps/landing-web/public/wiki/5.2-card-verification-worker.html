Purpose and Scope

This page details the implementation of the Card Verification subsystem within the SecureKit toolkit. It covers the Python-based card verification pipeline utilizing PaddleOCR for text extraction and OpenCLIP for visual and semantic similarity comparison, alongside the C# orchestration bridge (CardPython and CardVerification) that manages process lifecycles, virtual environments, and JSON-lines communication.

1. C# Orchestration and Process Bridge (CardPython & CardVerification)

The C# API layer interacts with the card verification Python worker via standard input/output redirection using a JSON-lines conversational protocol. The CardPython class implements ICardPython to locate the Python runtime, initialize the worker process, handle handshakes, and manage timeouts and process failure recovery.

JSON-Lines Conversational Protocol

The communication between C# and the Python worker proceeds via standard streams:

  1. The process starts and emits a ready event ({"event": "ready", "ok": true}) apps/securekit-api/Services/CardPython.cs 115-120
  2. Converse intercepts this handshake and sends the payload containing paths to the probe image, reference directory, and matching threshold apps/securekit-api/Services/CardPython.cs 121-122

2. Pipeline Architecture (PaddleOCR + OpenCLIP)

The Python card verification worker combines optical character recognition with visual feature embeddings:

  • PaddleOCR: Extracts textual fields from identification cards or badges, enabling text-based structural validation alongside visual checks.
  • OpenCLIP: Computes high-dimensional visual embeddings of the probe card image and compares them against registered reference images using cosine similarity or metric distance thresholds.

3. Configuration and Execution Files

The card verification worker relies on configuration files (config.yaml and config.cpu.yaml) to define model parameters, execution devices (CPU vs. CUDA/GPU), image preprocessing resolutions, and similarity thresholds.

  • Environment Separation: CPU-only deployments utilize config.cpu.yaml to disable hardware acceleration requirements, making it suitable for lightweight preflight checks or containerized environments lacking dedicated GPUs.
  • Error Handling: Missing Python dependencies trigger a specific PYTHON_DEPENDENCY_MISSING failure code, advising operators to install python/card_verification/requirements.txt in the targeted virtual environment apps/securekit-api/Services/CardPython.cs 83-86
