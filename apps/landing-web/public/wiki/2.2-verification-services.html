The service layer in apps/securekit-api orchestrates multi-modal biometric authentication, risk evaluation, session tracking, and network inspections. It acts as the business logic intermediary between HTTP controllers and underlying mechanisms such as file-based storage, network checkers, and isolated Python worker scripts.

For detailed breakdowns of specific sub-systems, refer to the child pages:

1. Service Layer Architecture and Responsibilities

The verification service layer separates concerns across biometric verification pipelines, security evaluations, and state persistence. C# service classes encapsulate the validation rules, input preprocessing, and response normalization required before returning decisions to the HTTP endpoints.

3. Keystroke, Risk, and Session Management

Beyond biometric matching, the toolkit evaluates authentication requests through behavioral dynamics and risk scoring models.

  • Keystroke Biometrics: Analyzes timing metrics (dwell time, flight time) for both dynamic typing challenges and fixed-text passwords. Profiles are updated dynamically using Exponential Moving Averages (EMA).
  • Session Risk Evaluation: The SessionRiskEvaluator combines signals from recent authentication attempts, anomaly detection, challenge verification status, and IP/network checking (NetworkVerification) to produce a composite risk score resulting in an allow, step_up, or deny decision.
  • State Stores: Transient challenges and active user sessions are managed via in-memory or file-backed stores (ChallengeStore, SessionStore).

For comprehensive implementation details on keystroke feature extraction, profile storage, and risk scoring logic, see Keystroke, Session and Risk Services.
