This section provides a high-level overview of the client-side architecture of SecureKit, which encompasses the browser-facing TypeScript SDK (@securekit/web-sdk), the shared contracts and logic package (@securekit/core), and the React demonstration playground (apps/demo-web).

For in-depth technical details, implementation specifics, and module internals, refer to the respective child pages:

4.1. @securekit/web-sdk Overview

The @securekit/web-sdk package provides the browser-side interface for interacting with authentication endpoints, capturing user biometrics, and tracking contextual signals. It encapsulates transport logic, keystroke event collectors, location/network context handlers, and legacy client compatibility adapters README.md 23

For detailed coverage of client.ts, transport layers, keystroke collectors, adapters, and legacy support surfaces, see @securekit/web-sdk.

Sources: README.md 23

4.2. @securekit/core Contracts and Orchestration

The @securekit/core package serves as the foundational shared layer across the monorepo. It defines request/response contracts, biometric processing modules, risk evaluation policies, and the client orchestration logic required to evaluate multi-modal signals README.md 21

For detailed information regarding shared contracts, biometrics modules, risk policies, the orchestrator, and default policies, see @securekit/core Contracts and Orchestration.

Sources: README.md 21

4.3. demo-web Application

The demo-web application is a React and Vite-based playground (apps/demo-web) designed to test registration, login, consent flows, and multi-modal biometric profile verification README.md 15 It integrates with both the @securekit/web-sdk and @securekit/core packages apps/demo-web/package.json 16-17

For details on the Vite development proxy, backend target resolution (api-target.ts), the AuthApp UI, authentication flows (auth.html), and acceptance smoke test scripts, see demo-web Application.
